# R18 implementation notes

- Matched the actual R7 reference and CSS, rather than the misleading shorthand “widest”: the R7 clock’s `font` declaration reset stretch to 100. The original and current Archivo file SHA-256 hashes are identical. Weight 900, solid edges and tabular digits remain; positive spacing needs a slightly smaller phone size. See `clock/metrics.json` and the four side-by-side comparisons.
- Unified supplemental glyphs under Archivo with matching variable-font descriptors. Otherwise a narrow Unicode subset could shadow the main face at normal width, silently selecting a system font despite correct computed CSS. The browser regression now checks actual font loading, and the static test checks matching subset descriptors.
- Backup codes come from a signed-cookie, no-store read endpoint. The endpoint returns only an already-issued code belonging to that identity; no code is placed in localStorage or public snapshots. Practice verified recovery with the displayed code. One recovery per rehearsal avoids intentionally exceeding the five-per-network recovery limit.
- Native feedback dialogs supply modal semantics and Escape handling; explicit Tab cycling also covers WebKit configurations that omit buttons from normal Tab navigation. No production feedback was submitted by testing.
- The source font allowlist, form-role checks, three-family exports, one-line frames, sentence-case supporting copy and 4% grain implement `BRAND.md`. Mathematical minus signs remain text; the leaderboard’s gold marker is now a drawn SVG.
- Older browser assertions still described superseded flows and copy. They now verify the current three-claim flow, current error messages, progressive share controls and the 60–75-second fallback update interval. Assertions were retained for ownership, strikes, rollover, downloads, keyboard use and accessibility.
- Sitemap failures were reproduced with an unavailable/malformed archive API and fixed with a valid 200 XML fallback. Robots no longer depends on the archive API. The historical Search Console failure is not conclusively attributable without its crawl logs.
- IndexNow’s committed key is public ownership proof, not a credential. Deploy notifications and archive-close notifications catch failures and use bounded timeouts; failures cannot invalidate a successful release.
- No new remote 200-player load run: FIXES-R12 §5.6 permits skipping when unable to wait until 7:05 PM ET, which is after R18’s 3 PM production cutoff. The small practice rehearsal stayed well within the account-wide budget. Local concurrency/load tests remain in the unit suite.
- An additional whole-catalog glyph audit found missing non-Latin characters in the expanded 4,050,546-entry catalog. All four OG coverage fonts are byte-identical to R17; this is an existing coverage limitation, not a new R18 regression. No catalog entries were altered or fourth font added. See `catalog-glyph-coverage.json`.

## Cloudflare setting audit: owner verification required

Cloudflare accepted the zone lookup but denied all security-setting/rules reads with HTTP 403 (`cloudflare-bot-audit.json`). The connected dashboard browser was unavailable. No security setting was changed, and no claim is made that the private WAF configuration was verified. Googlebot/Bingbot user-agent curls test endpoint responses, not Cloudflare’s verified-bot classification.

In **Cloudflare → dibs.here → Security → Settings**, filter **Bot traffic** and inspect **Bot fight mode**. If Super Bot Fight Mode is present, its **Verified bots** action should be **Allow**. Inspect **Security → Security rules** for Block/Challenge rules that could match known search crawlers; the supported exclusion is `and not cf.client.bot`. Review the corresponding Security Events before changing a rule. No specific blocking toggle was identified because its state could not be read.

Official references: [Bot Fight Mode settings](https://developers.cloudflare.com/bots/get-started/bot-fight-mode/), [verified-bot custom-rule exclusions](https://developers.cloudflare.com/waf/custom-rules/use-cases/allow-traffic-from-verified-bots/), [security interoperability](https://developers.cloudflare.com/waf/feature-interoperability/).

## First release attempt

The first production smoke caught missing home JSON-LD: the intentionally static home route bypasses Pages middleware. The release driver immediately rolled back both deployments, and a follow-up preservation check confirmed all existing player rows and the schedule were unchanged. The fix embeds the same graph into the static production HTML, replaces it exactly once on rewritten routes, and omits it from practice builds and private routes rewritten by middleware. A build-transform regression and browser assertion cover this path. The original fast home routing remains unchanged. See `attempt-1/` for the failed smoke and successful rollback evidence.

The refreshed Firefox run found one test click racing initial leaderboard layout: its trace showed the loading section intercepting the first pointer attempt, then the footer moving during the next pointer press/release. The dialog test now waits for the loaded leaderboard and fonts before interacting; its visibility, focus, Escape, submission, error and accessibility assertions are unchanged. Application code was unchanged. The full Firefox run was repeated.
